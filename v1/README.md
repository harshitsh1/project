# SDPO v1 — Teacher-Student DPO (Knowledge Distillation via Preference Pairs)

> A larger Qwen2.5-7B teacher model generates multiple candidate responses per prompt, a heuristic scorer picks the best and worst, and a smaller Qwen2.5-1.5B student learns from these preference pairs via Direct Preference Optimization (DPO).

**GitHub:** [https://github.com/harshitsh1/project.git](https://github.com/harshitsh1/project.git)

---

## Problem Statement

Train a small language model (1.5B) to produce better responses by learning from preference pairs generated by a larger, more capable model (7B). The 7B teacher generates multiple response candidates per prompt using varying repetition penalties, a multi-feature heuristic scorer selects the best and worst candidates, and the student is fine-tuned with DPO to prefer the higher-quality responses.

---

## Pipeline Overview

```
┌─────────────────────────────────────────────────────────────────┐
│ Step 1: Load UltraFeedback prompts (streaming)                  │
└──────────────────────────┬──────────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────────┐
│ Step 2: Teacher (7B, 4-bit NF4) generates 3 candidates/prompt   │
│         repetition_penalty = [1.0, 1.25, 1.5]                  │
│         greedy decoding (sampling crashes on 4-bit NF4)         │
└──────────────────────────┬──────────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────────┐
│ Step 3: score_response() ranks candidates (8 heuristic features)│
│         best → chosen,  worst → rejected                        │
│         skip if spread < threshold or chosen == rejected        │
└──────────────────────────┬──────────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────────┐
│ Step 4: Teacher unloads — free VRAM for student                 │
└──────────────────────────┬──────────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────────┐
│ Step 5: Student (1.5B, bfloat16 + LoRA) trains with DPOTrainer │
│         on (prompt, chosen, rejected) triples                   │
└──────────────────────────┬──────────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────────┐
│ Step 6: Before/after evaluation with score_response()           │
│         saves eval_report.json + training_plot.png              │
└─────────────────────────────────────────────────────────────────┘
```

## Scoring Heuristic — `score_response()`

Eight features combine into a single float score used to rank candidates:

| Feature | Points | Condition |
|---|---|---|
| Length adequacy | 0 to +2.0 | Scales with word count up to 80 words |
| Refusal penalty | −3.0 | Any refusal phrase detected |
| Code detection | +2.0 | Code prompt AND code markers found in response |
| Explanatory keywords | +0.3 each, max +1.5 | "defined as", "for example", "refers to", etc. |
| Structure bonus | +0.5 | Bullets, numbered lists, or headers present |
| Vocabulary richness | 0 to +1.0 | Unique word ratio |
| Hallucination penalty | −2.0 | Fake URLs or image markdown detected |
| Repetition penalty | 0 to −2.0 | Repeated trigram ratio |

**Spread threshold:** Pairs with `max_score - min_score < threshold` are flagged `[WEAK]`. Pairs where `chosen == rejected` are skipped entirely.

## Dataset

**UltraFeedback** (`trl-lib/ultrafeedback_binarized`) loaded via streaming.

- User turns extracted from the `chosen` messages
- 300 prompts in large mode, 20 in small mode
- 90% train / 10% eval split after pair generation
- 10 prompts reserved separately for before/after comparison

**Pair generation stats (300 prompts, large mode):**
- ~270–290 valid pairs typically produced
- ~10–30 skipped (identical candidates or < 2 generated)
- Average spread: **0.81** (visible as dashed red line in plot)

## Teacher Model

**Model:** `Qwen/Qwen2.5-7B-Instruct` loaded in **4-bit NF4 quantization**

| Setting | Value |
|---|---|
| Quantization | 4-bit NF4 (BitsAndBytes) |
| Compute dtype | float16 |
| Double quantization | Yes |
| Candidates per prompt | 3 |
| Generation mode | Greedy (do_sample=False) |
| Repetition penalties | 1.0, 1.25, 1.50 |
| Max new tokens | 80 |

Greedy decoding is used because temperature sampling causes `torch.multinomial` crashes on 4-bit quantized models due to NaN logits. Varying `repetition_penalty` forces different generation paths to create diversity between candidates.

## Student Model

**Model:** `Qwen/Qwen2.5-1.5B-Instruct` in bfloat16 with LoRA

| Parameter | Value |
|---|---|
| LoRA rank (r) | 16 |

## Training Results (v1)

| Metric | Value |
|---|---|
| Score BEFORE training | **2.62** |
| Score AFTER training | **2.34** |
| Improvement | **−10.6%** |
| Avg DPO pair spread | **0.81** |

### Reading the Plot

**Left panel — Evaluation Score (Before/After):**
The student scores 2.62 before DPO training and 2.34 after — a −10.6% regression. This is a known failure mode of teacher-student DPO with a weak heuristic scorer. Three factors explain it:

1. **Scorer mismatch** — `score_response()` rewards length and structure. The 7B teacher generates verbose, well-structured responses that score high. After DPO, the student tries to mimic this style, but Qwen2.5-1.5B cannot reproduce the same verbosity reliably, leading to responses that are verbose but incoherent — penalized by the repetition and vocabulary richness features.

2. **Weak pair spread** — The average spread of 0.81 is low. Most pairs (the tall bars on the left of the histogram at spread 0–0.5) are barely distinguishable. DPO requires strong contrastive signal; with near-identical chosen/rejected pairs, the model receives confusing gradients.

3. **Distribution mismatch** — The 7B teacher's output distribution is far from what the 1.5B student can produce. DPO tries to push the student toward responses it is not capable of generating, causing drift rather than improvement.

**Right panel — DPO Pair Score Spread Histogram:**
The distribution is right-skewed with most pairs concentrated at spread 0–0.5, a peak at 0.3–0.5, and a long tail to spread 5.0. The average spread of 0.81 (red dashed line) is pulled rightward by the tail. The ideal DPO training distribution would be centered at 1.5–2.0+ with fewer near-zero pairs. The large number of low-spread pairs is the primary driver of the regression — they give the model inconsistent training signal.

---

## Why This Matters (Motivation for v2+)

v1 demonstrates the classic limitation of teacher-student DPO: it requires a good scorer and genuinely diverse candidates to produce useful preference pairs. v2 removes the external teacher entirely, v3 adds verifiable evaluation, v4 replaces the heuristic scorer with NLI entailment, and v5 adds GRPO advantage estimation — each version directly addressing a failure mode visible in v1.

## Comparison Across Versions

| Version | Algorithm | Teacher | Loss | Key limitation |
|---|---|---|---|---|
| **v1** | **DPO** | **External 7B** | **DPO contrastive** | **Heuristic scorer, weak spreads** |
| v2 | True SDPO | Self (no EMA) | Top-K KL | No eval split, coarse feedback |
| v3 | SDPO + eval | Self (no EMA) | Top-K KL | No advantage signal |
| v4 | SDPO + NLI | Self (no EMA) | Top-K KL | No GRPO baseline |
| v5 | SDPO + GRPO | Self + EMA | JSD hybrid | Scale (1.5B limit) |
